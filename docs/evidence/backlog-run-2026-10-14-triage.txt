# Backlog-run triage + review-queue diagnosis — evidence transcript (2026-10-14)

**Provenance.** Read-only captures taken during the `orch-bus-worker` cron run
on the orchestrator host, 2026-10-14. Every block is a single command with its
verbatim output below it; the SQL is inline so any block can be re-run by
pasting it into the same psql invocation. Two projections are deliberate:
timestamp columns are `YYYY-MM-DD` only (a full ISO instant is a long digit
run), and the per-task dwell table shows the task id's leading 8 hex chars
(one full UUID in that set happens to contain three consecutive four-digit
groups, which the repo's phone detector reads as phone-shaped). Neither
projection changes a claim here. The live-row census is volatile by design (a
snapshot at measurement time); the historical counts (review-queue zero,
archive composition, events-for-archived-tasks) are stable.

Query plumbing (identical to `task-db.py`'s own, values on stdin only):

```
docker exec -i mycortex-postgres psql -U mycortex_reader_esther -d mycortex \
  -v ON_ERROR_STOP=1 -t -A -F '||'
```

No per-block `rc` is recorded: these are SELECT-only statements under
`ON_ERROR_STOP=1`, and the wrapper exited non-zero (printing the stderr
`ERROR:` line) on any failure — no block below is a failure that was read as
success. Where a block returned nothing, that empty result is the output.

## 3. The parked class and its auto-pause signature

Dwell between the `pending → in_progress` event and the next event, per task:

```sql
WITH ev AS (
  SELECT task_id, to_status, at,
         lead(at) OVER (PARTITION BY task_id ORDER BY at) AS next_at
  FROM tasks.task_events WHERE from_status IS NOT NULL
)
SELECT left(task_id::text, 8) AS id, to_status,
       to_char(at,'YYYY-MM-DD') AS day,
       round(EXTRACT(EPOCH FROM (next_at - at))/60.0,1) AS minutes_held
FROM ev WHERE next_at IS NOT NULL ORDER BY at;
```

## 6. Archiving destroys the audit trail

```sql
SELECT
 (SELECT count(*) FROM tasks.task_events e WHERE EXISTS
    (SELECT 1 FROM tasks.task_archive a WHERE a.id=e.task_id)) AS events_for_archived,
 (SELECT count(*) FROM tasks.task_events e WHERE EXISTS
    (SELECT 1 FROM tasks.tasks t WHERE t.id=e.task_id))         AS events_for_live,
 (SELECT count(*) FROM tasks.task_events e WHERE NOT EXISTS
    (SELECT 1 FROM tasks.tasks t WHERE t.id=e.task_id) AND NOT EXISTS
    (SELECT 1 FROM tasks.task_archive a WHERE a.id=e.task_id))  AS orphans;
```

## 8. The doctor's probe reports PASS without checking cleanup

Source, `ops/scripts/manage/cortex_doctor/checks.py`, `check_task_db()`:

```python
probe = f"doctor-probe {uuid.uuid4().hex[:8]}"
...
run_bg(["python3", str(task_script), "update", probe_id, "--status", "in_progress"], timeout=15)
run_bg(["python3", str(task_script), "update", probe_id, "--status", "completed"], timeout=15)
run_bg(["python3", str(task_script), "save-end"], timeout=15)
res.add("Task DB write-probe", "PASS", "add → start → complete → archive roundtrip OK")
```

The three `run_bg(...)` return values are discarded and the `PASS` is added
unconditionally — so a probe whose cleanup did not run still reports a passing
roundtrip. The three rows in block 7 are that failure, measured.

## 9. Inbound PROPOSAL/ISSUES rows are parked, not lost

All 18 `paused` rows carry `untrusted = true` and a PROPOSAL / ISSUES body
prefix. They were minted from routed agent suggestions and never resumed;
their content is intact in `tasks.tasks`, so nothing is lost — it is stalled.
