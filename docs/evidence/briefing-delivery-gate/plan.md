# PLAN — briefing-delivery-gate (cycle 13484, task 762379ca)

## Problem (measured, not asserted)

The daily sustainability briefing is generated by the LLM cron
`local-daily-sustainability-briefing` (07 6 * * *) and delivered to its own
chat. A canonical checker already exists
(`ops/scripts/sustainability/verify_briefing.py`: sections / `Source:` lines /
600-1200 words / .md+.docx+.pdf non-trivial / binaries carry the text), but
nothing runs it against what was actually DELIVERED. Drift therefore went
unnoticed for a week (2026-10-09 .. 10-15) until a manual probe.

Still true today — the delivered artifacts, checked by the canonical checker
itself, in this cycle:

## Seam that owns the decision

The orchestrator daily no_agent watchdog
`ops/scripts/orch-daily-regression-gate.sh` (cron `orch-daily-regression-gate`,
`15 3 * * *`, silent on PASS, alerts its chat on non-zero). It already runs a
golden suite daily; it is the existing machine-enforced "something must be
wrong for you to hear from me" surface on this host.

## Change (files)

1. NEW `ops/scripts/sustainability/check-latest-briefing.py` — host-local,
   stdlib-only. Locates the newest delivered `sustainability-briefing-*.md`
   under `--dir` (default `~/.hermes/cron/output`), decides applicability by
   reading `--jobs` (default `~/.hermes/cron/jobs.json`) for an enabled job
   whose name contains `sustainability-briefing`, then runs the canonical
   `verify_briefing.main(date, dir)` by import (its entrypoint is behind
   `if __name__ == "__main__"`, so the import is inert).
   Exit contract: `0` + empty stdout = PASS or not-applicable;
   `1` + report = the delivered briefing FAILS the canonical checker, or is
   stale; `3` + report = COULD NOT VERIFY (cron enabled but no artifact, or
   the imported entrypoint returned something other than 0/1).
2. `ops/scripts/orch-daily-regression-gate.sh` — after the suite PASSes, run
   the checker through the already-resolved capability interpreter
   (`python-with-module.sh zipfile`), and report + non-zero on its 1/3.
   Watchdog silent-on-pass contract preserved.
3. `ops/scripts/cortex-update.sh` — `register()` the new script exactly like
   its five siblings in the same block.
4. `tests/test_check_latest_briefing.py` — hermetic; drives the shipped
   script as a process over temp fixtures: not-applicable (no jobs entry),
   PASS (silent), FAIL (names the failing check), stale, and no-artifacts
   could-not-verify. No live cron or live briefing in any assertion.

## Explicitly rejected

- Editing the LLM cron prompt to "run the checker" — prose, not a gate; the
  row demands a machine-enforced control (SOUL P6).
- Creating a new no_agent cron — no `cronjob` tool in this session, and a
  new job would also drift from the cron manifest.
- Hand-editing `~/.hermes/cron/jobs.json` — unsanctioned write path.

## Uncertainty

The gate's own failure delivery is `deliver: telegram:<operator chat>`; the
report line names the artifact and the failing check, so the alert is
actionable without opening the repo. The gate is nightly (03:15), so worst
case a drifted briefing is reported ~21 h after delivery — accepted as the
limit of the existing mechanism, and stated in the evidence rather than
implied.
