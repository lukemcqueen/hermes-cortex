6. THE CEILING — stated, not hidden
   Same uid means this is prevention-for-the-careless plus attribution-for-the-deliberate.
   Escapes that REMAIN after both layers, and why each is still better than silence:
     1. A scripted `--no-verify` (inside a .sh) skips the hook entirely. Layer 1 only sees
        commands the agent TYPES, so a bypass hidden in a script reaches neither layer. It is
        already logged: the hook writes a sentinel and post-commit-audit records the miss.
     2. ssh-localhost ancestry laundering: a commit over loopback is rooted at sshd and reads
        as human. Needs the agent to add its own key (measured: refused right now, no key).
     3. Editing this hook, or setting the repo's core.hooksPath — same-uid, always available.
   Scheduling the commit (cron / at / systemd-run) is NOT on this list any more: the
   classifier fails CLOSED for any ancestry that is neither the runtime nor a login program.
   Only privilege separation — a second unix account, where sudo needs a password — makes
   any of these impossible rather than attributable.
