What was built
--------------
1. `ops/scripts/manage/land-when-clean-probe.sh` (this repo; registered in
   cortex-update.sh, deployed to ~/.hermes-cortex/scripts/) — a deterministic,
   LLM-free probe: it reports how many of the given paths still have uncommitted
   changes, whether origin's default branch is already an ancestor of HEAD, and
   whether a named commit has landed on origin. Stable output is the point: it
   lets a cron `monitor:` suppress the agent run entirely (no tokens while
   waiting).

   Usage:  land-when-clean-probe.sh [--repo DIR] [--landed-commit SHA] PATH [PATH...]

   HERMETIC TEST (re-executable, not prose): `tests/test_land_when_clean_probe.py`
   builds throwaway repos (including a bare `origin`) and asserts the exact
   outputs and exit codes. Measured just now:

     $ python3 tests/test_land_when_clean_probe.py
     ALL PASS (8 cases)
       dirty path -> blockers=1 ; staged change -> blockers=1 ; clean path -> 0 ;
       landed=n/a without --landed-commit ; two runs byte-identical ;
       commit pushed to origin -> landed=yes + origin_integrated=yes ;
       unpushed commit -> landed=no + origin_integrated=no ;
       no paths -> exit 2 + usage on stderr ; unreachable repo -> exit 0, fields "unknown"

2. A host-local wrapper for this host's paths —
   ~/.hermes-cortex/scripts/local-esther-land-nonhermes-fix-probe.sh — `local-`
   prefixed so the deployer preserves it and the doctor does not flag it as a
   stale deploy (verified: the doctor's "Stale deploy" count stays at 1, the
   pre-existing scripts/review-sweep-check.py). Its landing test is CONTENT, not
   a SHA and not a subject: a SHA is rewritten when another session rebases this
   shared branch (observed: a commit of ours was rewritten 120758c2 -> 09d27193
   with byte-identical content), and a subject can match an unrelated commit. So
   it asks origin/main's copy of mcp-servers/loop-gov-mcp.py whether it actually
   CONTAINS the fix (count of `_session_repo_path`), which cannot be rebased away
   or faked by a message.

3. Cron job `esther-land-nonhermes-lock-fix` (job id c975d8f8aa25, created
   2026-10-09T23:01 KST, every 15m, workdir ~/hermes-cortex, monitor = the
   wrapper above). It wakes only when the probe's output CHANGES and then:
   merge origin/main -> cortex-dogfood.sh --force -> score + end_change (which
   writes the push receipt the pre-push gate demands) -> git push origin main ->
   verify-landed.py. Rails: MERGE never rebase (the branch holds other sessions'
   unpushed commits, which a rebase would rewrite), `git merge --abort` on
   conflict, never stash/commit/revert another session's files, never
   --no-verify, never force-push. While blockers != 0 it reports "not-yet".
