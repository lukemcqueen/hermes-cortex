Measured on esther, 2026-11-03, before any rename. These are the load-bearing
counts behind the plan.

## Filesystem / env facts
- `CORTEX_DEPLOY_HOME` is **NOT** set in the environment (`env`, `/etc/environment`,
  `/etc/profile.d/` all empty) — each script's own
  `${HOME}/.hermes-cortex` default is active.
- Deploy-home default lives at `ops/scripts/cortex-update.sh:183`:
  `CORTEX_DEPLOY_HOME="${CORTEX_DEPLOY_HOME:-${HOME}/.hermes-cortex}"`.
- Same filesystem (`/dev/sda2`), so `mv` is renaming, not copying.

## systemd user units
- `~/.config/systemd/user/` carries the path in **65 files** (per
  `grep -rl 'hermes-cortex'`), covering `cortex-bus.service`,
  `cortex-gateway.service`, `cortex-gateway-esther0001.service`,
  `hermes-cortex-dashboard.service`, `health-vector.service`, and the ~20
  `cortex-bridge-*` service/timer pairs.
- No `/etc/systemd/*` (system) units reference it.
- Unit files are generated by `install-crons.sh` + `install-orch-crons.sh`
  under `$CORTEX_DEPLOY_HOME`, so regeneration rewrites the path.
