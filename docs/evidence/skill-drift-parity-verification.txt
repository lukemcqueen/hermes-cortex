Error policy — exactly what the script does
-------------------------------------------
A dependency whose run is not EVIDENT is a FAILED check, never a pass
(SOUL Principle 12). Exit codes alone are ambiguous for these tools, so each
check states its own run-evidence test:

  C1 cortex-doctor — exits 1 whenever ANY warning exists, so rc cannot separate
     "ran fine, warnings present" from "crashed". The check requires the tool to
     have emitted >= 100 per-check lines (measured: 470) or it reports
     COULD NOT VERIFY. It then fails only on a drift line carrying the warning
     glyph.
  C2 reconcile-stranded-skills.py — must print a line matching
     `verdict: (PASS|FAIL)`; anything else is COULD NOT VERIFY. FAIL is a real
     finding (stranded files exist), not a tool failure.
  C3/C4/C5 — an explicit `[ ! -f ... ]` guard for BOTH the repo and the deployed
     copy precedes any diff/awk, so a missing file cannot make an empty result
     read as "nothing wrong". C4 additionally inspects diff's own exit code
     (>1 means diff could not run -> COULD NOT VERIFY).
  C6 secret-leak-detector — measured behaviour: rc=0 with EMPTY output is the
     clean case; rc=0 with a report is judged on the blocking count; ANY
     non-zero rc or an unrecognised report is COULD NOT VERIFY.
