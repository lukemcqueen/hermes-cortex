## Reconciliation against the pass's OWN count (never silently overwrite)

The pass resolved, at its own instant: 28 sessions / 38 user rows / 5 prose
rows. This regeneration prints 27 / 38 / 6. Both deltas are explained, and
neither is drift:

  - sessions 28 -> 27: the pass's extra session is THIS RUN'S OWN session.
    A SESSION is bound by `COALESCE(last_activity_at, started_at)`, and at
    the mining instant this run's own `last_activity_at` was still <= the
    frozen end bound; it has since advanced past it. (Rows in a session are
    unaffected: a ROW is selected by its own `timestamp`.)
  - prose 5 -> 6: a DEFECT in the pass's own classifier, corrected here. The
    pass tested whether a machine marker appeared ANYWHERE in the first 200
    chars; the skill's rule is to drop only rows that OPEN with one (after
    lstrip). The stricter test dropped a real operator request that quotes a
    peer's report. The skill patch lands with this artifact.
