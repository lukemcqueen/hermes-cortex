## Objective
Build our own model, from the ground up, that does some of the functionality of
**Dev[in]-style code agents** — or a smaller specialized model. This document is the
research basis for deciding *what to build*, *how*, and *at what cost*. It is not a

## Three paths — honest framing
"From the ground up" has two very different readings, and the third is what the field
actually does:

| Path | What it is | Data needed | Compute (cloud) | Timeline | Best for |
|------|-----------|-------------|-----------------|----------|----------|
| **1. True from-scratch pretrain** | Design arch, build tokenizer + data, train every weight | Millions of examples (FineWeb-Edu etc.) | ~$200 (1B, 1 wk) to $500–5k+ | Weeks–months | Proprietary formats, genuinely new architecture, learning the pipeline |
| **2. Fine-tune a small open base** | Start from Qwen2.5-Coder / SmolLM / Mistral, adapt via LoRA/QLoRA | 100s–10,000s samples | **$10–$100/run** | Hours–days | **The realistic 80% case** — domain/agent specialization |
| **3. Distill a large teacher** | Use big model to emit high-quality trajectories; train small student on them | Teacher-generated | $200–2,000 (dominated by teacher inference) | Days–weeks | Shrinking LLM agent capability into a deployable SLM |

**Recommendation leans Path 2 (or 2+3):** specialize a small open-weight *code* base.
This is exactly what Devstral-Small and SWE-Gym do — the two projects most on-target
for "a Dev-like but smaller model."

## The canonical blueprint: Devstral-Small (the closest existing match)
**Devstral-Small** (Mistral AI + All Hands, arXiv:2509.25193) is a 24B model specialized
for *code agents*, the best open model below 100B size, outperforming Qwen-3 (235B) and
DeepSeek-V3 on SWE-bench via the OpenHands scaffold. Its recipe is literally the answer
to "how do you build a Dev-like specialized model":

1. **Base model:** dense Transformer from Mistral Small 3 (40 layers, GQA, 128k context).
2. **Data — the crux:** generate *supervised trajectories* by running an agent in
   **SWE-Gym** environments with the **OpenHands CodeAct scaffold**. Unit tests determine
   whether the final patch is correct (executable ground truth, not human labels).
   Plus a *selected natural-language mixture* to retain general ability.
3. **Two-stage post-training:**
   - Stage 1: SFT on the larger rollout set passing a *heuristic* quality filter.
   - Stage 2: SFT only on trajectories passing the *strictest* filters.
   - Then: **policy optimization (RL)** on additional rollouts generated by the
     fine-tuned model itself.
4. **Evaluation:** OpenHands scaffold, bash + file-edit tool, iterative protocol
   (≤3 attempts, temp 0→0.1), ~50 iterations is the sweet spot (auto-aborts).

**Transferable lesson:** the *data recipe* (agent-environment trajectories + executable
unit-test filtering + two-stage SFT + RL) matters more than model size.

## The open data foundation (don't hand-build this)
- **SWE-Gym** (arXiv:2412.21139) — first environment for training real software-engineering
  agents; open trajectories + models. Fine-tuning Qwen2.5-Coder-32B on just **491 trajectories**
  gave +12.3% absolute on SWE-bench Verified. Tiny data, huge win.
- **OpenHands-Sampled-Trajectories** (HF: `SWE-Gym/OpenHands-Sampled-Trajectories`) — ready-made.
- **OpenHands CodeAct** scaffold — the standard agent harness for generating + evaluating.
- **Qwen2.5-Coder** — 0.5B / 1.5B / 3B / 7B / 14B / 32B, the workhorse small code base.
- **SmolLM2 / FineWeb-Edu** — for true from-scratch (the $200 proof used this).

## The agentic-RL layer (stage 3)
Open-source recipes exist and are directly reusable:
- **Open-AgentRL** (Gen-Verse) — open RL for LLM agentic scenarios: SFT cold-start →
  **GRPO agentic RL** on Qwen2.5-7B / Qwen3-4B, RLVR coding, released policy+reward
  checkpoints. DemyAgent-4B = "SOTA from RL data."
- **TRL** (HuggingFace) — shipped `SFTTrainer`, `DPOTrainer`, `GRPOTrainer`, `RLOOTrainer`;
  GRPO is the memory-efficient agentic-RL path (fits ~7B in 24 GB).
- **TorchTitan** — PyTorch-native 4D-parallelism pretraining (use ONLY for the true
  from-scratch path; it is not for fine-tuning).

## Compute cost anchors (real, from community $200 experiment + industry guides)
From Edwin Kalio's published ~1B-from-scratch run (DigitalOcean droplets):

| GPU | VRAM | $/hr | Note |
|-----|------|------|------|
| RTX 4000 Ada | 20 GB | $0.76 | data prep, small runs |
| L40S | 48 GB | $1.57 | main 1B training |
| H100 | 80 GB | $3.39 | too costly for small budget |

- True from-scratch ~1B: **~$200, ~1 week** (FineWeb-Edu ~4.2B tokens).
- Fine-tune a small base with LoRA/QLoRA on cloud: **$10–$100**, hours.
- Distillation: **$200–$2,000** (teacher-inference-dominated).

Memory: QLoRA fine-tunes a 7B on a single 24 GB consumer card; a 1B + Adam fits ~48 GB.

## Recommended concrete path (if we proceed)
A **Path-2/3 hybrid**, smallest viable version of Devstral:

1. **Pick base:** `Qwen2.5-Coder-1.5B` or `-3B` (open, small, strong-native-code; not the
   instruction-tuned variant — use base so our agent format dominates).
2. **Generate trajectories:** run OpenHands CodeAct over **SWE-Gym** instance subset;
   keep trajectories that make the **unit tests pass** (executable filter). Reuse the
   open `OpenHands-Sampled-Trajectories` set to bootstrap — no need to generate from zero.
3. **Stage-1 SFT (LoRA):** on OpenHands agent format, heuristic-filtered rollouts.
   Evaluate against a held-out SWE-bench subset.
4. **Stage-2 SFT:** strictest-filter trajectories only.
5. **Agentic RL (GRPO):** reward = patch passes tests (executable), using Open-AgentRL
   GRPO recipe or TRL `GRPOTrainer`.
6. **Serve:** small enough for CPU/Ollama or a single small GPU; deploy like any local model.

**Staged investment (de-risk first):** prove with the cheapest slice (LoRA SFT on
`-1.5B` over ~491 open trajectories, ~$50–150 cloud) and measure SWE-bench before
spending on RL or a bigger base. This is the "prove on one small case, then scale" rule.

## Key risks / honest caveats
- **"From the ground up" ≠ from-scratch pretraining in practice.** Every successful small
  agent model (Devstral-Small included) is a *specialization of an open base*, not a cold
  pretrain. From-scratch only wins for genuinely proprietary/narrow domains.
- **Evaluation is the hard part.** Need the OpenHands harness + SWE-bench subset; a model
  that "looks good" on samples will be wrong without executable-test grounding.
- **Agentic RL is unstable** (reward hacking, mode collapse). GRPO is the memory-safe pick;
  keep a reference model + KL term.
- **This host has no GPU** — all training runs on rented time; keep models small.
