## Why the leaves matter

A repo commit leaves the host's *runtime* on the old name where it was installed before the
rename. The transition symlinks make old paths *resolve*, so nothing crashes — but the host is
not canonical until the live bits repoint. Un-canonical surfaces, confirmed on esther:

- **git hooks** — `core.hooksPath` and the hook symlinks pointed at `~/.hermes-cortex/…`.
- **systemd/launchd units** — `ExecStart`/`WorkingDirectory` and bridge-unit paths pointed at
  `~/hermes-cortex/…`; the renamed cron `agent-hermes-cortex-sync` still had bridge units that
  fired the now-deleted `agent-hermes-cortex-sync.sh`.
- **Deployed stale scripts** — old-name copies of renamed/removed scripts remained in
  `~/.steadfaste-fleet/scripts/` (the doctor lists them as `⚠ Stale deploy`).
- **Root-owned copies** — `/usr/local/sbin/fix-blocked-ips.py` (Linux) kept `hermes-cortex`
  paths until `sudo deploy-fix-blocked-ips.sh` reloaded it.
- **Orphaned PENDING governance cycles** from a session that ended without scoring — these
  block the push until scored.

## Per-host completion steps

Run in this order on a freshly-pulled, freshly-deployed host (`git pull` + `fleet-update.sh`
first — that is what puts the swept sources on the host). Orchestrators: each write below is a
governed action; `begin_change` a cycle named for it and close it.

### 1. Repoint git hooks + `core.hooksPath`

```bash
# Confirm what's stale:
git config --global core.hooksPath        # expect ~/.steadfaste-fleet/hooks
git -C ~/steadfaste-fleet config core.hooksPath
ls -la ~/.steadfaste-fleet/hooks/ | grep -- '->'   # targets read hermes-cortex → stale

# Unlock the immutable hooks dir as the orchestrator, repoint, relock:
sudo -n /usr/local/sbin/hermes-plugin-lock unlock --orchestrator
ln -sf ~/.steadfaste-fleet/scripts/pre-commit-score        ~/.steadfaste-fleet/hooks/pre-commit
ln -sf ~/.steadfaste-fleet/scripts/pre-push-pull           ~/.steadfaste-fleet/hooks/pre-push
ln -sf ~/.steadfaste-fleet/scripts/post-commit-audit       ~/.steadfaste-fleet/hooks/post-commit
ln -sf ~/.steadfaste-fleet/scripts/post-push-audit         ~/.steadfaste-fleet/hooks/post-push
ln -sf ~/.steadfaste-fleet/scripts/prepare-commit-msg-session ~/.steadfaste-fleet/hooks/prepare-commit-msg
sudo -n /usr/local/sbin/hermes-plugin-lock lock

git config --global core.hooksPath ~/.steadfaste-fleet/hooks
git -C ~/steadfaste-fleet config core.hooksPath ~/.steadfaste-fleet/hooks
```

### 2. Regenerate the cron-bridge units + drop the stale sync units

The cron `agent-hermes-cortex-sync` was renamed to `agent-steadfaste-fleet-sync`; the bridge
units are not regenerated by a deploy.

```bash
python3 ~/steadfaste-fleet/ops/scripts/cortex-bus-bridge-generate.py   # regenerate units from the current cron manifest
rm -f ~/.config/systemd/user/cortex-bridge-agent-hermes-cortex-sync.service \
      ~/.config/systemd/user/cortex-bridge-agent-hermes-cortex-sync.timer \
      ~/.config/systemd/user/timers.target.wants/cortex-bridge-agent-hermes-cortex-sync.timer
systemctl --user daemon-reload
systemctl --user enable cortex-bridge-agent-steadfaste-fleet-sync.timer
```

### 3. Repoint standalone unit paths

Any unit whose `ExecStart`/`WorkingDirectory` reads `hermes-cortex` (e.g. `fleet-gateway*`,
`hermes-cortex-dashboard`, `health-vector`) — sweep the path token, then `daemon-reload`:

```bash
grep -rl hermes-cortex ~/.config/systemd/user/   # list them first
# edit each `hermes-cortex` path token → `steadfaste-fleet`, then:
systemctl --user daemon-reload
systemctl --user restart fleet-gateway health-vector hermes-cortex-dashboard 2>/dev/null
```

### 4. Remove stale deployed scripts

The doctor lists these as `⚠ Stale deploy … not in any register() mapping` — remove them:

```bash
rm -f ~/.steadfaste-fleet/scripts/agent-hermes-cortex-sync.sh \
      ~/.steadfaste-fleet/scripts/verify-rename-esther.sh \
      ~/.steadfaste-fleet/scripts/fleet-doctor.py \
      ~/.steadfaste-fleet/scripts/fleet-update.sh \
      ~/.steadfaste-fleet/scripts/nightly-handoff.py
rm -rf ~/.steadfaste-fleet/scripts/fleet_doctor
```

Leave anything the doctor marks `Not repo-owned (a Hermes default, or a plugin install)` — that
belongs to its owner, not the repo.

### 5. Reload the root-owned copy (Linux; macOS: `/usr/local/bin`)

```bash
sudo bash ~/steadfaste-fleet/ops/install/deploy/nginx/deploy-fix-blocked-ips.sh
```
The root copy is immutable and root-owned, so this needs the operator's sudo (agents cannot run
it). On macOS the equivalent path is `/usr/local/bin` and the deploy script is platform-aware.

### 6. Score orphaned PENDING cycles

A session that ended without scoring leaves a PENDING cycle that blocks every push on the host:

```bash
# find it (id, task_id, session_id, decision):
python3 -c "import sqlite3;c=sqlite3.connect('$HOME/.steadfaste-fleet/data/loop-governance.db');[print(r) for r in c.execute(\"SELECT id,task_id,session_id,decision FROM loop_cycles WHERE decision='PENDING'\")]"
```
Score it by `cycle_id` (never `task_id` for another session's row) via
`feedback_accept(cycle_id=<id>, …)` with an `unscored_reason`.

### 7. Verify

```bash
python3 ~/steadfaste-fleet/ops/scripts/manage/fleet-doctor.py --quiet   # 0 fail
curl -fsS 127.0.0.1:8903/health                                          # 200 (bus)
grep -rl hermes-cortex ~/.config/systemd/user/ /usr/local/sbin/          # nothing
grep -rl 'hermes-cortex' ~/.steadfaste-fleet/scripts/                    # nothing but the transition tools
```

## macOS (Titus) differences

- **launchd, not systemd** — the sync/health/gateway jobs are launchd plists in
  `~/Library/LaunchAgents`; sweep `hermes-cortex` path tokens the same way and `launchctl
  unload/load` the affected plists. `docs/macos-service-layer.md` is the service map.
- **Root copies in `/usr/local/bin`** (not `/usr/local/sbin`), `chflags` not `chattr`.
- **`hermes-plugin-lock` lives at `/usr/local/bin`** and `chflags uchg` works as the owner —
  no sudo needed for the hook repoint.
- **No systemd** means no bridge-timer regeneration; the macOS cron bridge uses launchd
  equivalents. Same rule: drop any launchd job still named `agent-hermes-cortex-sync`.

### macOS: repoint the Pi-harness + agent surfaces (required before removing the symlinks)

> **This is an ALL-HOSTS step, not macOS-only** (proven on esther/Linux 2026-11-06): every host
> carries the same tool-visible surfaces pointed at the transition symlink, and removing the
> symlink before repointing them breaks the gateway's MCP servers and the harness configs.

**Linux (esther) — the Hermes tool-visible keys** (complement the Pi-harness list below; both
were still resolving the transition symlink after §1–§7):

- `~/.hermes/config.yaml` — `mcp_servers.*.command` + `args` for agent-bus, tasks, executor,
  review, loop-governance (5 servers / 10 `~/.hermes-cortex/…` refs). File-writing tools REFUSE
  config.yaml as security-sensitive, so repoint with `hermes config set <dotted.key> <value>`
  (list values as JSON): `hermes config set mcp_servers.review.args '["…", "--role", "review"]'`.
- `~/.hermes/repos.yaml` — `path: ~/hermes-cortex` / `name: hermes-cortex` → `~/steadfaste-fleet`
  / `steadfaste-fleet` (lesson-harvesting registration).
- `~/.hermes/skills` + `~/.agents/skills` + `~/.hermes/scripts` symlinks — repoint DIRECT to
  `~/.steadfaste-fleet/<name>` (`ln -sfn ~/.steadfaste-fleet/skills ~/.hermes/skills`), dropping
  the `~/.hermes-cortex/` hop. A missed one left dangling by symlink removal fails the doctor's
  `Cron runtime scripts` check (`~/.hermes/scripts missing`).
- `local-*` wrappers in `~/.steadfaste-fleet/scripts/` that `exec ~/.hermes-cortex/scripts/…` or
  pass `--repo ~/hermes-cortex` (e.g. `local-clickhouse-log-cleanup.sh`,
  `local-esther-land-nonhermes-fix-probe.sh`) — repoint the exec path AND the `--repo` argument.
- **The mycortex brain's LOCAL source** (measured 2026-11-06 — the fix feels like a no-op until
  the sync cron fires): `mycortex.sources.local_path` for a source registered at the OLD repo
  path (`/home/<user>/hermes-cortex`) still points there, so the sync sees 0 pages and the
  mass-deletion guardrail aborts: `'<name>': mass-deletion guardrail: N/N pages would archive
  (>10%)`. Repoint via psql as `mycortex_admin` (preserves the source's federated flag — a
  `sources add` without `--federated` would silently un-federate it):
  `UPDATE mycortex.sources SET local_path = '/home/<user>/steadfaste-fleet' WHERE name = '<name>';`
  Then verify: `~/.steadfaste-fleet/scripts/mycortex sync --source <name>` shows `N seen,
  0 archived`, and `agent-mycortex-sync` (systemd bridge) records success.

The running gateway's MCP servers were SPAWNED with the old paths and keep running through symlink
removal; a later `hermes mcp reload` / gateway restart re-spawns them from the repointed
config.yaml. Repoint everything FIRST, verify `grep -rl hermes-cortex` is clean across the
tool-visible keys, then remove the symlinks.

## What is deliberately kept

The names below are stable identifiers, not stale paths — do **not** sweep them:

- The enforcer's sanctioned-command regexes accept **both** `hermes-cortex|steadfaste-fleet`
  (transition compatibility).
- `hermes-cortex-dashboard.service` — the dashboard service keeps its name.
- The `hermes-cortex`, `hermes-cortex-setup`, `hermes-cortex-repo-deploy`,
  `hermes-cortex-maintenance` **skills** — concept names, not paths.
- Historical `hermes-cortex` mentions in `docs/evidence/` and `docs/older/` — migration records.
- The transition tools themselves: `fleet-set-origin.sh`, `migrate-home-dirs.sh`,
  `verify-rename-local.sh` reference the old paths on purpose.
