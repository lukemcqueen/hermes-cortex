# Live Test 2026-08-24 — Messaging Gateway end-to-end proof

Session record for the gateway's first REAL-WORLD test (Luke: "you better
test this before saying anything is done"). The live test caught THREE
things the mock E2E missed — this is the evidence and the debug trail.

## What was proven

Full outbound path, human-confirmed:
`agent reply → bus (out_esther) → running gateway → envelope validate →
Telegram sendMessage → Luke's DM` (round-3 message, confirmed by Luke).

## The three live-test findings

### 1. Bus `/api/pgmq/read` returns `body` as a DICT, not a JSON string

The mock returned body-as-string; the real bus returns the envelope object
directly. `json.loads(msg.get("body"))` on a dict raises TypeError — and if
uncaught, the message requeues on visibility timeout forever (silent
non-delivery). Fix (commit cd68611f): accept both shapes:

```python
body = msg.get("body")
if isinstance(body, str):
    try: body = json.loads(body)
    except ValueError: body = None
```

**Rule: mocks that return body-as-string are too forgiving.** Verify a
consumer against the REAL bus, not just mocks.

### 2. Shim queue-direction collision (commit 689ffc7b)

The first `agent-shim.py` polled `out_<AGENT>` as "instructions for the
agent" — but the gateway DRAINS `out_<AGENT>` to send replies to the app.
A shim poll would steal the agent's own replies before delivery.

Correct contract: `inbox_<AGENT>` = FOR the agent (gateway writes, shim
polls); `out_<AGENT>` = FROM the agent (shim replies, gateway drains).

**Rule: never add a second reader to a queue a daemon drains — check the
consumer role first.**

### 3. Auth paths (nginx masks Bearer)

| Path | Auth | Trap |
|------|------|------|
| External nginx port (`:13004`) | Basic | Bearer masked → 401 |
| Direct local uvicorn (`127.0.0.1:8903`) | Bearer | Basic → 401 |

A daemon with BOTH `CORTEX_BUS_TOKEN` + `CORTEX_BASIC_AUTH` set picks
Bearer, silently 401s through nginx, and `urllib` errors swallow into
`{"msg_id": None}` — reads look "empty" with zero errors.

## Debug trail (the order that found the bugs)

1. Launched gateway outbound-only with real creds → message stayed queued
2. Probed bus read manually → 403 (stale nginx Basic perms on `out_*`)
3. Added `out_*` permission row for esther → still 403 via nginx
4. Tested direct uvicorn (8903) with Bearer → 200 (auth-path discovery)
5. Re-pointed gateway at direct path → message still not draining
6. Read the queue with the gateway's own `bus_read` → body-as-dict bug
7. Fixed wire shape + restarted → drained + archived + delivered

## Permission grant that made it work

`out_*` read+write for esther (orchestrator, live-test scope). In prod the
gateway principal `gw-<host>` gets scoped `out_*` read per ADR-0005.

## Test discipline (Luke's standard)

1. Unit tests on pure logic
2. Mock E2E with the REAL daemon code
3. **Live test**: real bus + real bot + human confirmation in the DM
4. Verify the wire contract on the real bus (body dict; archive moved the
   message out of `bus.messages`)

Never claim "done" on messaging infrastructure without the live
human-confirmed round trip.
