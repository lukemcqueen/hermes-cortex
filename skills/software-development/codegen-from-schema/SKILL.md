# Codegen from a canonical schema (committed artifacts + CI diff gate)

Build a code generator that emits **shape-only** code from one JSON-Schema that
is the single source of truth, commits the generated files, and makes CI FAIL on
manual divergence. This is the "codegen is PRIMARY, not a fallback" pattern.

## The core discipline

- **A `build.rs` that silently regenerates on every build is wrong** for this
  pattern: it rewrites the committed file on every build, so the CI divergence
  gate can never fire. Use a **standalone generator + committed generated files
  + a CI diff gate** (run the generator, `git diff --exit-code`); divergence
  must *fail*, never silently heal.
- **Generate shape, never logic.** The generator emits struct/enum definitions,
  `rename_all`, derive flags, field order, integer widths, `Option`-ness, and
  the serde attribute set. Policy (validators, negotiation, projections, byte
  framing) lives in hand-written `*_policy.rs` / `projections.rs` /
  `framing.rs` siblings the generator never reads — a schema-driven generator
  literally cannot emit a `deserialize_with` that points at hand-written logic
  unless you record that wiring as metadata.

## The recipe, in order

1. **Survey the real state first** — the handoff/plan may be stale. Grep the
   live schema `$defs` and the on-disk shape files before trusting any "HEAD /
   N tests green" claim; the repo often sits ahead of the plan it was handed.
2. **Settle the generator form with the owner** — standalone-generator +
   committed artifacts + CI diff gate is the anti-bloat default; a `build.rs`
   hides drift.
3. **Enrich the schema into a true codegen source of truth** (see
   `references/schema-as-codegen-source.md`). JSON-Schema as drafted is
   INSUFFICIENT for faithful regeneration: it lacks integer widths (`u16` vs
   `u64`), the enum rename-case (snake vs SCREAMING_SNAKE), the per-field serde
   set, and the frozen-semantics doc comments. Without `description` + a
   realization block on every `$def`, a generated file is not byte-equivalent to
   the hand-written one it replaces. Do NOT skip this and hand-code a
   realization table in the generator — that duplicated map is itself a
   hand-paralleled artifact that drifts from the schema.
4. **Register every new `$def` in the schema-completeness guard** in the same
   commit — a nested type promoted to a top-level `$def` breaks the inventory
   test until its name is added to the guard's type list.
5. **Refactor the generator to lib+bin** (`src/lib.rs` exposes a pure
   `generate(schema, target) -> Vec<(filename, content)>`; `src/main.rs` is a
   thin CLI) so the generator is a testable library — required both by the TDD
   Iron Law gate (a bin with no test is refused) and by the committed-match test.
6. **Write the two compiled CHECK tests** (in the generator crate, using
   `include_str!` with a path relative to the test file):
   - *idempotence* — two `generate()` calls over the same schema are byte-identical;
   - *committed-match* — `generate()` output equals the committed shape files
     byte-for-byte (via `include_str!("../../<crate>/src/<file>.rs")`).
7. **Prove the committed-match checker NON-VACUOUS** — append a line to a
   generated file and confirm the test FAILS, then restore. A diff check you
   have never seen fail proves nothing; a passing run alone is a vacuous
   assertion.
8. **Regenerate in place and move the non-shape content OUT in the same
   commit** — `impl Default`, `#[cfg(test)]` modules, and projection functions
   move to the hand-written siblings; the committed files AND the
   committed-match test's `include_str!` fixtures update together so the suite
   stays green at every commit.
9. **Wire the CI gate** — a job that runs the generator for each target and
   `git diff --exit-code` over the generated dirs. Committing the workflow file
   itself needs the GitHub PAT `workflow` scope to push.
10. **Do NOT run `cargo fmt -p <crate>` on a crate that holds generated
    files** — fmt rewrites the generated bytes and instantly breaks the
    committed-match test. Format only the hand-written files.

## A second schema under the same generator (do not fork it)

When the same recipe applies to a second schema (`--target surface` beside
`--target abi`), **generalize the one generator with a `Target`
{banner, schema_rel, out_rel, files}**, not a second crate duplicating the emit
logic. Give each target its own `banner` so the original target's files stay
byte-identical when you extend the generator.

## Pitfalls (each cost real time here)

- **`cargo run -p X --target Y` is a cargo flag, not yours.** Cargo's own
  `--target` sets the cross-compilation triple, so the arg never reaches your
  binary's switch — the run fails cryptically. Use `cargo run -p X -- --target Y`
  (bare `--` separates cargo args from the program's args) and write that exact
  form in help docs, or a future session parrots the broken version.
- **`serde_json::Map` is a `BTreeMap`, so JSON key order is LOST on parse.**
  Do not rely on `$defs`-map or `properties`-map insertion order to reproduce
  struct field order. Record field order EXPLICITLY as an ordered array in the
  schema's realization block; enum variant order may come from the `enum` array
  (an ordered list) but never from an object's key order.
- **A distinct schema→Rust name needs a name override.** A snake_case `$def`
  (`commission_data`) that should emit a PascalCase struct (`CommissionData`)
  will otherwise generate a snake_case type. Support a per-`$def` `name`
  override (and, for enum variants holding characters no Rust identifier can
  (dots), a per-variant name map) rather than renaming the schema keys — the
  completeness guard pins the schema's key names.
- **The committed-match test and the committed files are one unit.** Editing a
  generated file, changing the `banner`, or adding a generated module requires
  the generator output, the committed files, and the test's `include_str!`
  consts to move in one commit — a stale fixture reads as a false pass.
- **`pub use reads::*; pub use verbs::*;` glob re-exports keep consumer paths
  alive when hand-written types move into generated modules** — check what
  downstream crates reference (`steadfaste_surface::{Escalation, ...}`) and re-
  export the generated modules so the public surface does not relocate.
- **Re-verify the existing target is byte-identical after you generalize the
  generator** (before adopting the second target) — its committed-match test is
  the net; it must stay green without regeneration.
